Keyward

Your agent reads ~/.zshrc for perfectly ordinary reasons, and every token you exported leaves with it. So take the values off the disk.

The problemkeyward

Nobody made
a mistake

An agent opens your shell configuration to check PATH, or to work out why a variable is unset, or to read an alias. All reasonable. In doing so it pulls every exported token into its context window, and from there into a transcript that may be stored, replayed, or summarised somewhere you are not looking.

What is assumed

A hostile agent

Defended against with sandboxes, permission prompts, and audit trails. Rare in practice.

What happens

A helpful agent

Reads a readable file for a good reason. Happens constantly, leaks the same credentials, and no control is watching.

Scopekeyward

What this is not

Stated first, because a security tool that overstates its reach is worse than one that does less and says so.

Not an agent firewallNetwork egress control is solved and crowded. Complementary, not competitive.
Not enforcementNo sandbox, no wrapper, no interception of file reads.
Not proof against intentAn agent that can run commands can run a resolver. The accidental case closes; the deliberate one does not.
Not cross-platformmacOS only, so the Keychain replaces hand-rolled cryptography.
Not a team productOne machine, one person. Usefulness to others is a later question.

Architecture / layerskeyward

Separate the
two concerns

Layer one

Migration

Provides security. Values move to the Keychain; files hold references.

Needs no cooperation. Holds whether the agent behaves or not, because there is nothing on disk to find.

Layer two

Cooperation

Provides productivity. MCP tools, generated instructions, errors that name the next action.

Needs cooperation. Decides only whether the agent works smoothly or wastes turns hunting.

Keeping these apart is the central idea. Conflating them is how a tool ends up requiring a wrapper around every agent — and then going uninstalled.

Architecture / formatkeyward

cap://<name>

Chosen to survive every parser that will see it — dotenv, JSON, YAML, TOML, shell single-quoting. No $, no braces, nothing a shell will expand.

RuleReason
Prefix is case-sensitiveDetection stays unambiguous and needs no allocation.
Names lowercased on parsePrevents two Keychain items differing only by case.
a–z, 0–9, and - _ .Safe in every config format that will carry it.
Begins and ends alphanumericNo ambiguity at token boundaries.
Slashes rejectedLeaves namespacing open without committing to a scheme.

Architecture / internal/handlekeyward

Two decisions
inside the parser

Decision

IsRef is weaker than Parse

IsRef asks whether a string claims to be a reference. Parse decides whether it is a valid one.

So cap://bad name is recognised as a broken reference and fails loudly, rather than being handed to a program as though it were the secret.

Decision

Errors never quote input

Parse runs against strings that turn out to be real credentials, and an error message reaches a log file easily.

ErrNotHandle therefore carries no context at all. A test asserts a token-shaped input never appears in the error text.

Architecture / migrationkeyward

The tools that
write the files

Migration runs once per file. Everything after that is resolution.

internal/migrate

Take the values out

Detect secrets by known prefixes and names — ghp_, sk-, eyJ, Bearer. Store each in the Keychain, rewrite the line to a reference. Values that only look random are flagged, never moved.

Dry-run by default. Shows a diff. Keeps a backup. This is the adoption-critical component: if it is not trustworthy, nothing downstream gets used.

internal/mcpconfig

Rewire the servers

Rewrite each MCP server to launch through keyward, with references in its env block.

Also fixes a standing bug: servers currently fail with a connect timeout when the editor launches from Finder, because the variable is empty outside a login shell. Resolving from the Keychain makes launch method irrelevant.

Architecture / exposurekeyward

Prefer the first rung
that finishes the work

1
keyward run -- <cmd>
Resolve into the child's environment and exec. Values exist nowhere else.
2
keyward inject -- <cmd>
Same, plus a temporary file for tools that demand a credential path rather than a variable.
3
keyward shell
An interactive subshell holding real values. Explicit, time-boxed, and the only path where plaintext reaches your own environment.

Rejected: export TOKEN="$(keyward get TOKEN)" in the rc file. That puts real values into every shell, which the agent's own shell inherits — reintroducing the exact leak.

Architecture / trustkeyward

The agent may refer,
never resolve

Requests queue, a human approves, the command runs, and the agent receives the command's output — never the value. Gated, not blocked.

Chosen

Reference only

The guarantee is provable: one enforcement point, no templates to escape. Deletes the SQL validator, the argument constrainer, and the template engine along with the vulnerability class they existed to contain.

Rejected

Agent-spendable

More capable, but safety would rest on every command template being escape-proof forever. For a security tool, an unprovable guarantee is worth little.

The cost is friction. Time-boxed grants, batched approval, and plan-time approval are the mitigations — in that order of importance.

Architecture / storagekeyward

Keychain, not a
custom vault

The nearest comparable tool writes its own encrypted vault because it supports Linux. Being macOS-only is the advantage here, not the limitation.

Gain

No crypto

Nothing to implement, review, or get wrong.

Gain

Free ACLs

Per-item access control comes from the OS.

Gain

A door left open

Access-control flags make biometric gating conceivable later.

Do not shell out to security(1)

security add-generic-password -w <value> places the secret in argv, where ps can read it. Self-defeating for a secrets tool. Use cgo against SecItemAdd and SecItemCopyMatching.

Reality / invalidatedkeyward
Corrected

Deleting the file is
not enough

An earlier design replaced ~/.aws/credentials with credential_process, reasoning that there would then be nothing to read. That reasoning was wrong.

The hook is itself a resolver

aws configure export-credentials --format env prints plaintext to stdout, resolves through the credential_process chain, and has no documented way to be disabled. git credential fill is equivalent.

AWS's own documentation warns that credential_process "could be a security risk if the command to generate the credentials becomes accessible by non-approved processes" — which describes an agent exactly.

Every native credential hook is designed to be invoked by tooling, and an agent that runs shell commands is tooling. The invariant is scoped to match.

Reality / prior artkeyward

Someone already
built this

HASP ships the same invariant, nearly the same architecture, and seven agent integrations. Recorded so the position stays honest rather than flattering.

WhatWhere that leaves keyward
HASPRepo-scoped: project bindings, per-repo manifests, targets. A shell rc file is not in a repo, so this problem sits outside its model. Fair Core licensed, and no Keychain or biometric path.
Pipelock · CoderEgress firewalls. Complementary — they cover the sanctioned-use-then-print gap keyward cannot.
1Password op://The same primitive, mature. No per-caller attribution and no command scoping — support it as a backend rather than compete with the format.
MCP itselfThe spec tells stdio servers to read credentials from the environment. The ecosystem standardised on the problem.
